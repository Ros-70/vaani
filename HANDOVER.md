# Handover

Written at the end of the first autonomous build session. Assume the next
session has no memory of this one beyond the repo contents and this file.

## Status in one paragraph

A complete Kotlin/Jetpack-Compose Android project exists: the IME service,
its Compose keyboard surface (letters/symbols/more layers, tap/hold race,
long-press diacritics, dictation panel, edit row, suggestion strip), a Room
+ DataStore data layer, all seven companion-app screens, a whisper.cpp JNI
scaffold, and a unit + instrumented test suite. The app module's Kotlin and
Compose source was confirmed to actually **compile** against a real Android
SDK (set up from scratch in the sandbox this was built in — see "What was
and wasn't verified" below), and real bugs were found and fixed this way.
What has **not** been verified: an actual `assembleDebug` build (needs the
NDK + a real internet connection to fetch whisper.cpp — this sandbox's
network policy only allowed `dl.google.com`), running on a device/emulator,
and the instrumented test actually passing against the real keyboard. CI is
the first place all of that gets to happen for real.

## What was and wasn't verified, and why

This was built in a sandboxed cloud container with **no Android SDK/NDK
pre-installed** and a network policy allowing only `dl.google.com` /
`dl-ssl.google.com` plus package-manager traffic (no generic internet, no
`github.com`). Two things followed from that:

1. **A minimal Android SDK was set up from scratch** (command-line tools +
   platform 34 + build-tools, all from `dl.google.com`) specifically to
   verify this project for real rather than leaving it unverified. With
   that SDK, `:app:compileDebugKotlin`, `:app:compileDebugUnitTestKotlin`,
   and `:app:compileDebugAndroidTestKotlin` were all run for real and made
   to pass — this is how the two systemic bugs below were actually caught
   and fixed, not guessed at:
   - Every Compose file that read `val colors = LocalVaaniColors` was
     missing `.current` (that's the `CompositionLocal` itself, not the
     resolved palette) — every themed color in the whole UI was broken.
   - `import androidx.compose.foundation.layout.weight` resolves to an
     *internal* `RowColumnParentData` property of the same name instead of
     the `RowScope`/`ColumnScope` member extension function it looks like
     it's importing — that import should never have been written; the
     member needs no import inside a `Row`/`Column` content lambda.
2. **What still could not be verified here**: `./gradlew testDebugUnitTest`
   itself (not just compiling the tests) needs Robolectric's
   `nativeruntime-dist-compat` jar, whose Maven Central mirror
   (`gcp.mirrors.maven.org`) this sandbox's network policy explicitly
   denied (confirmed via the proxy's own status endpoint — a real policy
   denial, not a flake, so it wasn't retried). `assembleDebug` needs the
   NDK (not installed) and `app/src/main/cpp/CMakeLists.txt`'s
   `FetchContent` of whisper.cpp from `github.com` (not reachable here).
   **The very first real `./gradlew test`, `./gradlew assembleDebug`, and
   instrumented-test run for this project happen in CI** — read its first
   run's logs before assuming anything beyond what's listed above works.

If CI's first run fails, the most likely places, in rough order of how
untested they are:
- `app/src/main/cpp/jni_bridge.cpp` — written against whisper.cpp's public
  C API from documentation/memory, never compiled against the real
  `whisper.h`. Check `whisper_init_from_file_with_params`'s exact signature
  and `whisper_full_params` field names against whatever `v1.7.2` (pinned
  in `CMakeLists.txt`) actually has first.
- Exact dependency version numbers in `app/build.gradle.kts` — chosen from
  memory of what's compatible together (Compose BOM 2024.09.00, Room
  2.6.1, Navigation Compose 2.7.7, etc.) but never resolved end-to-end in
  this sandbox.
- The instrumented test's UI-Automator `By.text(...)` lookups assume
  Compose's `Text` composables expose their string as the accessible text
  UiAutomator searches by, which is standard but unverified on a real
  device here.

## What's left

- **Everything in "wasn't verified" above** — get a real `assembleDebug`
  and a real device/emulator run, and fix whatever that first real build
  surfaces.
- **The TRANSLIT dictionary is intentionally scope-limited** (per the build
  brief): it's the same small 16-word Latin→Devanagari lookup from the
  prototype, nowhere near enough for daily use. A real transliteration
  engine or library is a known, flagged stretch goal — not a blocker.
- **Streaming transcription** re-decodes the whole growing buffer on each
  chunk rather than true incremental decoding (DECISIONS.md #4) — correct,
  gets slower as an utterance grows long. Worth revisiting once the basic
  pipeline is confirmed working end-to-end.
- **IndicWhisper** (the fourth model in the Models list) is a community
  model not bundled with whisper.cpp — R will need to find/convert it
  separately, same as the build brief describes; nothing in the app blocks
  this, there's just no bundled pointer to one specific file.
- The acceptance checklist in the build brief has **not** been walked
  end-to-end on a real device (couldn't be, in this sandbox) — that's the
  single most important thing for whoever picks this up next to actually
  do, item by item, against a real phone or emulator with WhatsApp/Gmail/
  Notes installed.
- `applicationId`/package name (`com.vaani.keyboard`) and the whisper.cpp
  version pin (`v1.7.2`) were both picked without being able to check
  anything against a live network — sanity-check both still make sense.
